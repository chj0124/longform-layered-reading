# 验证说明

本目录提供可复现的合成用例、评分门槛和报告模板。用例存在不等于当前版本已经通过；只有 `reports/` 中保存了对应输入、实际输出、复核结果和版本信息，才能声称某项验证已通过。

## 用例

| 用例 | 主要回归风险 |
|---|---|
| `cases/concrete-reading-path.md` | 只有抽象标签；擅自补推断；细节被省略；简单文章仍默认 HTML |
| `cases/argumentative.md` | 独立理由被串成因果；预测被写成事实；限制或例子被遗漏 |
| `cases/research-one-limitation.md` | 补造第二项限制；相关被写成因果 |
| `cases/interview.md` | 多方声音被合并；语境丢失；虚构共识；补造引语日期 |
| `cases/narrative-dates.md` | 引语记录日期继承事件日期；事后解释被写成当时认识 |
| `cases/incomplete-source.md` | 片段被伪装成全文；未读部分被写成原文没有 |
| `cases/layering-density.md` | 主线堆长段；只留骨架而遗漏细节；拆句时丢条件 |
| `cases/html-interaction.md` | 核心正文被全部折叠；空旷排版割裂关联；死控件；浏览器检查误报 |
| `cases/execution-modes.md` | 日常档滑向摘要；未逐段回查；完整档缺清单；两档正文保真不一致 |

所有输入均为合成材料，不应用于证明任何现实事实。

## 运行流程

1. 记录待测提交 SHA、Agent／模型、运行日期、运行环境和执行档位。
2. 在无本技能的全新上下文中运行目标用例，保存基线输出；若只验证修订而非做对照实验，可标「未运行基线」，不得补写。
3. 在加载本技能的另一全新上下文中运行同一输入，保存实际输出。同一上下文自检须明确标注，不冒称独立盲评。
4. 按 `scoring-rubric.md` 逐项复核。完整档保存正式信息清单；日常档保存逐段回查记录，复核者可独立建立清单核验，但不得要求日常成品附 `Sxxx` 表。
5. 用 `report-template.md` 在 `reports/` 中保存结果、证据路径和未解决问题；记录关键连接数与主线时间。
6. 两档先检查带标记的主线候选，成稿后复测。长文主线优先实测 3—5 分钟；无法实测时运行 `scripts/estimate_main_path.py` 并明确标为估算。短用例不凑时长。
7. 完整档运行 `scripts/validate_content_map.py` 检查信息清单和覆盖统计；该脚本不能代替输出文本的双向回查。日常档不因此增加正式底稿。
8. HTML 日常档记录当前产物冒烟检查；完整档和模板变更按实际执行情况填写浏览器、键盘、焦点、紧凑密度、移动端和链接检查。未执行即写「未验证」，模板历史结果不能冒充当前产物结果。

## 通过条件

- 所有硬性门槛按当前执行档位通过；
- 评分达到 `scoring-rubric.md` 规定线；
- 报告包含实际输出和与档位匹配的覆盖证据，不接受只有「看起来符合」的结论；
- 日常档与完整档对照时，正文主线和细节不得因省略正式底稿而出现信息差；
- 修订规则后重跑受影响用例，不宣称未运行场景也已回归通过；仅呈现规则变更不必重跑无关文本场景。
