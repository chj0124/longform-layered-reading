# 验证说明

验证分三层：内容保真、主线路径与桥接、实际呈现。按执行档位与变更范围选择，不用形式记录代替实际行为。

## 档位要求

### 日常档

- 保存或简述轻量内容草图与实际逐段回查范围。
- 不强制 `Sxxx` 编号、完整内容地图或逐项覆盖表。
- 当前 HTML 实例至少完成打开、主线、展开／关闭、页内链接与占位符冒烟。
- 交付声明使用实际核对方式，不冒充逐项审计。

### 完整档

- 保存正式信息清单、唯一主要落位和覆盖数量。
- 未落位必须为 0；合并有去向，未读范围有声明。
- 按实际输出执行完整呈现检查并保存报告。

### 回退

结构、事实或覆盖不稳时，只补做受影响的完整检查。模板、样式或交互变更时，重跑受影响的 HTML 用例；不必为纯呈现变更重跑无关文本审计。

## 用例

- `cases/execution-modes.md`：同一篇原文分别运行日常档与完整档，比较正文是否实质一致。
- `cases/html-interaction.md`：验证主线可见、原生展开、链接、键盘、响应式、控制台和外部请求。
- 其他既有用例继续按各自目标使用。

## 两档对照

对照正文，而非只比较审计附件：

1. 比较主线问题、判断、推导、证据和边界。
2. 比较细节区的例子、数字、归属、条件和反例。
3. 比较关键桥接是否一致。
4. 允许日常档省略正式清单和覆盖表，不允许省略正文信息。

没有独立计时，不报告具体提速比例。若做速度实验，应使用独立全新上下文，记录任务、输入、起止时间与是否含验证，并区分生成耗时和阅读耗时。

## 报告

使用 `report-template.md`，按 `scoring-rubric.md` 评分。文本估算必须标明口径；浏览器、真实触屏、屏幕阅读器、真实读者与独立盲评只报告实际执行范围。

仓库内合成文本用于稳定复现结构与边界，不用于证明现实事实。真实文章试读可补充体验发现，但不能替代可重复的合成用例。
