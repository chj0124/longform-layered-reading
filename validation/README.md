# 验证说明

本目录提供可复现的合成用例、评分门槛和报告模板。用例存在不等于当前版本已经通过；只有 `reports/` 中保存了对应输入、实际输出、复核结果和版本信息，才能声称某项验证已通过。

## 用例

| 用例 | 主要回归风险 |
|---|---|
| `cases/concrete-reading-path.md` | 只有抽象标签；擅自补推断；细节被省略；简单文章仍默认 HTML |
| `cases/argumentative.md` | 独立理由被串成因果；预测被写成事实；限制或例子被遗漏 |
| `cases/research-one-limitation.md` | 补造第二项限制；相关被写成因果 |
| `cases/interview.md` | 多方声音被合并；语境丢失；虚构共识；补造引语日期 |
| `cases/narrative-dates.md` | 引语记录日期继承事件日期；事后解释被写成当时认识 |
| `cases/incomplete-source.md` | 片段被伪装成全文；未读部分被写成原文没有 |
| `cases/layering-density.md` | 主线堆长段；只留骨架而遗漏细节；拆句时丢条件 |
| `cases/html-interaction.md` | 核心正文被全部折叠；空旷排版割裂关联；死控件；浏览器检查误报 |

所有输入均为合成材料，不应用于证明任何现实事实。

## 运行流程

1. 记录待测提交 SHA、Agent／模型、运行日期和运行环境。
2. 在无本技能的全新上下文中运行目标用例，保存基线输出；若只验证修订而非做对照实验，可标「未运行基线」，不得补写。
3. 在加载本技能的另一全新上下文中运行同一输入，保存实际输出。
4. 按 `scoring-rubric.md` 逐项复核，并填写信息覆盖数、具体桥接数和主线时间；建议由未参与生成的人或独立上下文复核。
5. 用 `report-template.md` 在 `reports/` 中保存结果、证据路径和未解决问题。
6. 长文主线优先实测 3—5 分钟；无法实测时运行 `scripts/estimate_main_path.py` 并明确标为估算。短用例不凑时长。
7. HTML 用例必须按实际执行情况填写浏览器、键盘、焦点、紧凑密度、移动端和链接检查；未执行即写「未验证」。

## 通过条件

- 所有硬性门槛通过；
- 评分达到 `scoring-rubric.md` 规定线；
- 报告包含实际输出和覆盖清单，不接受只有「看起来符合」的结论；
- 修订规则后重跑受影响用例，不宣称未运行场景也已回归通过。
