# 用例：具体桥接、保真与 Markdown 分流

## 输入（合成原文）

**《社区图书馆该不该延时开放》**

社区应延长图书馆的晚间开放时间。许多上班族白天无法到馆，延长两小时能让他们使用座位与书籍。有人担心运营成本上升，但可先试行三个月，再根据到馆人数调整。若晚间读者持续过少，就恢复原时段，避免长期浪费经费。

用户未指定输出格式。

## 必须做到

- 这种单主线、浅层级结构优先用 Markdown 树状大纲，不默认生成 HTML。
- 标题可保留议题，但主线须明确「作者主张应延长晚间开放时间」，不能只写中性问题。
- 分别写清目标群体、白天痛点、晚间方案、方案收益、反方担忧、验证程序、观察指标、退出条件、退出动作与目的。
- 关键连接写具体桥接句，例如从上班族使用需求到晚间方案、从成本担忧到先试行。
- 保留「有人担心」的归属与不确定性，不把成本上升写成已证实事实。
- 保留「使用座位与书籍」和「避免长期浪费经费」。
- 「下班后图书馆已关门」若出现，只能标为推断；优先不补写这一原文未明述的事实。
- 「先试行三个月」是验证程序，「到馆人数」是观察指标，「持续过少」是退出条件，不统称为抽象「判断标准」。
- 短文不凑 3 分钟；时长估算使用 `--allow-short`。

## 禁止

- 只输出「痛点 → 约束 → 判断标准」等抽象标签。
- 为追求简短省略方案收益或退出目的。
- 把作者的应然主张改成没有立场的客观介绍。
- 为显得有逻辑而补造原文没有的闭馆事实或数据。
