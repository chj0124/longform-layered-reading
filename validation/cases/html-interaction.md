# 用例：HTML 分层与交互验收

## 输入

使用 `argumentative.md` 的合成原文，要求生成单文件交互 HTML。除该用例的内容要求外，执行以下实际检查。

## 静态检查

- 样式与脚本内嵌，无外部资源依赖。
- 一个 `h1`，标题层级不跳跃，`lang` 正确。
- 主阅读路径容器带 `data-main-reading-path`，只有短句骨架、具体桥接和必要推导；例子、数据位于对应细节层。
- 核心正文与论证链无需逐项展开即可阅读；长文主线按 3—5 分钟预算检查，短用例不凑时长。
- 结构总览有信息增益，关键连接不只显示抽象关系类型；推断关系（如有）单独标识。
- 无大面积 hero、全屏标题或装饰性留白；相关节点邻近，正文不小于 16px，紧凑但未形成文字墙。
- 每个展开控件都有新信息，无死按钮、空区块或装饰切换。
- 覆盖证据与执行档位匹配：日常档有实际逐段回查声明，完整档信息覆盖清单显示未落位数为 0；本次模板变更验证使用完整档。

## 实际浏览器检查

1. 打开默认层，确认主线、核心正文和具体关系可连续阅读，并记录主线时间检查方法。
2. 在桌面视口检查首屏密度、相关节点邻近性和关联可见性，不凭 CSS 直接判定通过。
3. 逐个操作展开控件，确认内容、ARIA 状态和实际开合同步。
4. 仅用键盘遍历全部控件；自定义复合部件另测方向键、Home／End。
5. 检查焦点顺序和可见性，尤其是 `overflow` 容器内的焦点框。
6. 在 390×844 视口检查页面无横向滚动、文字可读、密度合适且阅读顺序未丢失；表格自身容器滚动不视为页面溢出。
7. 检查链接、`aria-controls` 目标和可点目标尺寸。
8. 若执行 console 或触屏检查，记录方法和结果；未执行则明确写“未验证”。

## 禁止

- 只凭代码样式声称键盘、焦点或移动端已经通过。
- 把核心正文全部藏入折叠控件。
- 为追求“一屏看完”而删除原文细节。
- 用卡片、颜色和图标代替真实关系图，或用大留白把关联板块割裂。
- 为紧凑而把正文缩到 16px 以下、压小点击目标或形成文字墙。
