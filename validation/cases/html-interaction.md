# 用例：HTML 交互与当前产物验证

## 目的

验证 HTML 不是只「看起来能打开」，而是主线、细节、链接和键盘操作在实际浏览器中可用。按执行档位与变更范围选择检查深度。

## 日常档冒烟

对当前文章实例实际执行：

1. 打开本地 HTML，确认标题与当前文章一致。
2. 主线无需点击即可阅读。
3. 逐个展开、关闭 `<details>`，确认内容非空。
4. 点击页内链接，确认目标存在并到达。
5. 检查无 `%%…%%` 占位符、明显空白、内容错置和外部资源依赖。

模板历史结果不能替代上述当前产物检查。

## 完整档或模板／交互变更

在当前产物上执行并记录：

- 桌面视口与约 390px 移动视口。
- 主线直接可见，细节展开／关闭有效。
- 页内导航目标存在，点击后到达预期位置。
- 从页面默认状态按 Tab，焦点顺序与阅读顺序一致。
- 原生 `summary` 可用 Enter 与 Space 操作。
- 每个 Tab 停靠点有可见焦点框。
- 页面无横向溢出，多列在窄屏合理降为单列。
- 控制台无当前产物引入的错误，无意外外部请求。

## 覆盖证据

覆盖证据必须与执行档位匹配：

- 日常档：逐段回查范围与正文核对结果。
- 完整档：逐项编号、唯一落位、数量与未落位项。

不能因为页面能交互，就推定内容完整；也不能因为有覆盖表，就推定页面可用。

## 报告边界

真实触屏、屏幕阅读器、真实读者计时与独立盲评，未执行就明确写未执行。截图可用于目检，但是否入库由任务约束决定；截图不是功能通过的唯一证据。
