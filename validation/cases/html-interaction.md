# 用例：HTML 分层与交互验收

## 输入

使用 `argumentative.md` 的合成原文，要求生成单文件交互 HTML。除该用例的内容要求外，执行以下实际检查。

## 静态检查

- 样式与脚本内嵌，无外部资源依赖。
- 一个 `h1`，标题层级不跳跃，`lang` 正确。
- 一级只有短句骨架和逻辑关系；例子、数据和条件位于对应下级。
- 核心正文与论证链无需逐项展开即可阅读。
- 结构总览有信息增益，推断关系（如有）单独标识。
- 每个展开控件都有新信息，无死按钮、空区块或装饰切换。
- 信息覆盖清单显示未落位数为 0。

## 实际浏览器检查

1. 打开默认层，确认主线、核心正文和关系可连续阅读。
2. 逐个操作展开控件，确认内容、ARIA 状态和实际开合同步。
3. 仅用键盘遍历全部控件；自定义复合部件另测方向键、Home／End。
4. 检查焦点顺序和可见性，尤其是 `overflow` 容器内的焦点框。
5. 在 390×844 视口检查页面无横向滚动；表格自身容器滚动不视为页面溢出。
6. 检查链接、`aria-controls` 目标和可点目标尺寸。
7. 若执行 console 或触屏检查，记录方法和结果；未执行则明确写“未验证”。

## 禁止

- 只凭代码样式声称键盘、焦点或移动端已经通过。
- 把核心正文全部藏入折叠控件。
- 为追求“一屏看完”而删除原文细节。
- 用卡片、颜色和图标代替真实关系图。

## 验证记录

按 `validation/report-template.md` 保存实际输出、检查结果和未验证范围。没有实际运行时，本用例状态只能是“待验证”。
