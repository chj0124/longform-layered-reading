# 用例：同一原文的日常档与完整档

## 目的

验证日常档只减少正式底稿与覆盖记录，不减少正文信息。

## 合成原文

使用 `examples/content-map-example.md` 文末的《共享工具间的使用规则》合成原文。该原文只用于规则验证，不代表现实机构或实际安全规程。

## 操作

1. 日常档：建立轻量草图，按原文顺序逐段回查，输出主线与细节，不制作正式 `Sxxx` 表。
2. 完整档：建立 `S001—S019` 信息清单与唯一落位，输出主线、细节和覆盖审计。
3. 比较两档从主线开始到按需细节结束的正文。
4. 分别检查交付声明是否与实际档位一致。

## 通过标准

- 两档正文实质一致，允许不改变信息的排版差异。
- 核心问题、三个条件、两类示例结果和工具对比均保留。
- 日常档没有逐项编号审计，但有实际逐段回查声明。
- 完整档 `S001—S019` 连续、唯一落位，未落位为 0。
- 不根据同一上下文中的先后生成声称具体提速比例。
