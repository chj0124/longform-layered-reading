# 交互模式、紧凑排版与实现要求

仅在输出候选含交互 HTML 时加载。先按轻量内容草图或正式内容地图中的关系选择交互模式，再实现；交互不得反向创造逻辑。日常档优先复用 `assets/compact-reading-template.html`，不为每篇重新做设计研究；需要改变公共模板或交互时，执行完整呈现验证。

## 关系 → 交互映射

### 1. 独立支撑 → 分支后汇聚

- 顶层分支与轻量内容草图或正式内容地图中的独立支柱一一对应；支柱内部机制、案例和证据不提升为顶层分支。
- 并列分支视觉汇合到同一判断节点，每支可展开证据与限定条件。
- 不把独立理由排成互为前因的单线链；推断关系不得升级成原文明示。

### 2. 必要前提／连续论证／连续机制 → 顺序链

- 用文字和具体桥接句区分必要性、论证承接与机制顺序，不把顺序自动写成因果。
- 顺序链逐节点展开；连接处呈现「什么内容通过什么步骤推出下一内容」，箭头可展开原文依据。
- 不为显得有机制而添加原文没有的环节。

### 3. 共同作用 → 并列因素指向共同结果

- 并列因素同层呈现，共同指向结果；共同作用不等于每个因素必不可少。
- 不伪装成先后因果，不写成「缺一不可」，不拆成独立支撑而丢失共同作用。

### 4. 反馈 → 循环图（受限）

- 仅原文存在可回指的反馈路径时使用；单向先后不得画成循环。

### 5. 对照 → 切换视图或对照表

- 仅比较主体共享稳定维度时使用；维度不稳定改用结构化短句。
- 作者判断与预测就近标注，不混作比较维度。

### 6. 时间 → 时间线

- 节点按原文时间顺序排列，可展开细节、引语与来源。
- 记录日期与事件日期分别标注；时间先后不写成因果。

### 7. 部分—整体／类别—实例 → 展开或下钻

- 整体在主线，局部细节与实例在下级；通常保持约 2—3 层。
- 展开必须提供默认层没有的内容，不制造重复或空控件。

### 8. 阐释／延伸外推 → 就近说明或独立延伸区

- 阐释就近展开；预测、建议和外推与结论分区并标归属，不并入事实链。

## 关系图与阅读引导

1. **结构总览**：多节点 HTML 至少提供一幅短句骨架总览，显示阅读顺序、节点及具体关系；每个节点只保留一个短关系句，不重复后续章节的完整说明。单一主线且节点很少时不必升级 HTML。
2. **复杂逻辑可视化**：多支柱、前提链、连续论证、共同作用、对照、反馈等关系使用相应图形或交互，不只留线性文字。
3. **具体连接**：连接线上或紧邻位置必须有桥接句，写清起点内容、推理／条件与终点内容；关系类型只能作辅助标签。
4. **逐关系有依据**：每条箭头与「独立」「汇聚」「缺一不可」等措辞都回指轻量内容草图或正式内容地图；推断用文字和样式双重标识。
5. **信息增益**：图形必须减少、重组或显化关系；卡片、标签、颜色和图标本身不算关系图。
6. **避免重复**：同一内容不得用同等长度正文和等价图表重复呈现；不同关系不得为凑少图而合并。
7. **短句节点**：图内节点使用短标题或短句，细节位于对应下级。

## 紧凑排版契约

紧凑的目标是让关联同时可见，不是把文字挤小。

1. **无展示型开场**：不使用大面积 hero、全屏标题、装饰性首屏或大留白；首屏尽快进入核心问题与主阅读路径。
2. **相关节点邻近**：有直接关系的节点优先同组、相邻或局部连线；在常见桌面视口中尽量让一组推导同时可见，不用遥远卡片迫使读者来回滚动。
3. **密度预算**：正文默认不小于 16px，行高约 1.5—1.7；段落间距约 0.25—0.5em，节点内边距与节点间距以 8—12px 为默认起点，主要区块间距以 12—20px 为默认起点。可按内容微调，不用超大 padding、margin 制造空旷感。
4. **卡片受限**：只有需要界定一组关系或细节时才用卡片；不把每个短句都做成独立大卡片，不用阴影和圆角代替层级。
5. **分组而非拥挤**：保留必要留白区分不同关系组；不得为紧凑形成文字墙、压扁点击目标或隐藏核心论证。
6. **移动端保序**：窄屏转为线性布局时保留编号、具体桥接和细节归属，不因堆叠而失去阅读顺序；表格可在自身容器滚动。
7. **实际检查分档**：日常档至少检查当前页面可打开、主线直接可见、原生展开可展开／关闭且内容非空、页内链接有目标；完整档及模板变更至少检查默认桌面视口与 390×844 视口的密度、关联可见性和横向溢出，并按控件检查键盘、焦点、ARIA 和 console。未执行则写未验证，不凭 CSS 或模板历史结果声称当前产物通过。

## 固定实现要求

1. **单文件无依赖**：样式与脚本内嵌，不引用外部资源，双击即可打开。
2. **主线标记**：主阅读路径容器带 `data-main-reading-path`；主线直接可见，细节位于对应下级。
3. **完整可回认**：每项有信息量的原文内容都有输出位置；日常档通过逐段回查确认，完整档通过逐项落位确认；页面不得只展示骨架。
4. **结构引导一致**：编号、缩进、箭头、桥接句和逻辑标签全篇一致；首次出现提供图例。
5. **展开新信息**：每个控件展开后呈现默认层没有的内容；无行为按钮、空区块和装饰切换不得出现。
6. **原生控件优先**：展开用原生 `<details>/<summary>`，互斥展开用同名 `name` 分组；确需 `hidden="until-found"` 时监听 `beforematch` 同步状态并提供回退；不给原生 `<button>` 叠加 Enter／Space 键盘处理。
7. **键盘**：Tab 可达全部控件；自定义复合部件支持方向键与 Home／End；保留可见 `:focus-visible`，焦点顺序符合阅读顺序；`overflow` 容器不得裁掉焦点框。
8. **ARIA 与语义**：ARIA 状态与行为一致；每个 `aria-controls` 有目标；一个 `h1`，标题逐级不跳级；标题不放在 `<summary>` 内，需作触发时用「标题包按钮」；`lang` 正确。
9. **移动端**：响应式排版用 `clamp()` 组合视口与字号单位，不单独使用裸 `vw`；390×844 下页面无横向滚动、文字可读；可点目标不小于 24×24 CSS 像素，触屏环境进一步加大。
10. **如实报告**：默认层、展开、切换、键盘、焦点、紧凑密度、移动视口与链接按实际检查记录；未执行即写未验证。
