# 交互模式：关系映射与固定实现要求

仅在步骤 4（输出候选含交互 HTML）加载。先按内容地图的关系选择交互模式，再实现；交互不得反向创造逻辑。

## 关系 → 交互映射（适用条件与反例）

### 1. 独立支撑 → 分支后汇聚

- **结构契约**：
  1. 页面顶层分支与内容地图中的独立支柱一一对应，不预设数量。
  2. 支柱的机制、案例、证据与子条件渲染在该分支内部，不成为顶层分支。
  3. 只有原文明示的独立支撑才使用本模式；不得为了让图形对称，把推断关系升级为原文的独立支撑。
- **交互形态**：并列分支视觉汇合到同一决定节点；每支可展开证据、案例与限定条件。
- **验收检查**：顶层分支数等于内容地图的独立支柱数；机制、案例、证据和子条件不得带有顶层“理由 N／支柱 N”标签。
- **反例**：排成使一理由成为另一理由前因的单线链；合并独立理由；把内部支撑提升为顶层支柱。

### 2. 必要前提／连续论证／连续机制 → 顺序链

- **适用条件**：前一环节是后一环节成立的必要前提，后一论证承接前一论证，或机制按原文顺序逐步展开。三者用文字标签区分，不把顺序自动写成必要性或因果。
- **交互形态**：顺序链逐节点展开，每个箭头可展开原文依据。
- **反例**：把独立支撑误排成前提—结果链；箭头无依据；为显得有机制而添加原文没有的环节。

### 3. 共同作用 → 并列因素指向共同结果

- **适用条件**：原文呈现多个因素共同作用、指向同一结果。共同作用不要求每个因素必不可少；仅原文明确确立必要性时才使用必要性措辞。
- **交互形态**：并列因素同层呈现，共同指向结果节点。
- **反例**：伪装成先后因果；把贡献性因素写成“缺一不可”；拆成独立支撑而丢失共同作用。

### 4. 反馈 → 循环图（受限使用）

- **适用条件**：仅当原文存在可回指的反馈路径（A 强化或削弱 B，B 又回指 A）时使用。
- **反例**：把单向先后画成循环；用循环图装饰没有回路的原文。

### 5. 对照 → 切换视图或对照表

- **适用条件**：两个以上主体、方案或情境共享稳定比较维度。
- **交互形态**：按钮切换视图或并列对照表；比较维度不稳定时改用结构化短句。
- **反例**：列维度不稳仍强行切换或制图；把作者判断混为比较维度。

### 6. 时间 → 时间线

- **适用条件**：事件按原文时间顺序发展。
- **交互形态**：节点按序排列，可展开细节、引语与来源；记录日期和事件日期分别标注。
- **反例**：把时间先后写成因果；打乱原文顺序；为引语补造日期。

### 7. 部分—整体／类别—实例 → 展开或下钻

- **适用条件**：整体在一级，局部细节或实例在下级；通常保持约 2—3 层，不为形式制造过深层级。
- **交互形态**：一级只放短句节点，下级放对应原文信息；展开必须提供一级没有的内容。
- **反例**：展开与一级实质重复；为装饰制造无新信息控件；细节离开所属节点集中堆放。

### 8. 阐释／延伸外推 → 就近说明或独立延伸区

- **适用条件**：阐释用于解释已有概念或判断；预测、建议和外推作为原文结论之外的延伸判断保留。
- **交互形态**：阐释就近展开；延伸外推与结论分区并标明归属，不并入事实链。
- **反例**：把作者预测画成事实结果；用外部背景替代原文解释。

## 关系图与信息图表（全部 HTML 输出必须满足）

1. **结构总览**：多节点 HTML 至少提供一幅短句骨架总览，显示节点及其关系；单一主线且节点很少时，可用结构化导航代替，不装饰凑图。
2. **复杂逻辑必须可视化**：多支柱、前提链、连续论证、共同作用、对照、反馈、时间和局部—整体等复杂关系必须使用相应图形或交互视图，不得只留长段线性文字。
3. **信息增益**：图形必须减少或重组文字，或承载文字难以线性表达的关系；仅把卡片、标签、颜色摆成图形不算信息图表。
4. **逐关系有依据**：每条箭头与“独立”“汇聚”“缺一不可”等措辞都必须回指内容地图；推断关系用文字和样式双重标识。
5. **数量以不同关系为限**：每个视图至多一幅总览图；每个核心节点的每种不同关系至多一幅机制图或对照图。同一内容不得用同等长度文字和等价图表重复呈现；不同关系不得为凑少图而合并。
6. **短句节点**：图内节点使用短标题或短句，不将整段原文塞入图节点；图的细节同样放在对应下级。

## 固定实现要求（全部 HTML 输出必须满足）

1. **单文件无依赖**：样式与脚本全部内嵌，不引用任何外部资源，双击即可打开。
2. **信息分层**：一级只显示骨架和关系；原文细节位于对应下级。核心正文与论证链无需逐一操作控件即可连续阅读，折叠只用于辅助细节、背景和按需下钻。
3. **完整可回认**：交付前按信息清单核对每个原文信息单元的输出位置；页面不得只展示骨架而遗漏下级信息。
4. **结构引导一致**：标题、编号、缩进、箭头和逻辑标签全篇一致；首次出现提供图例，不只靠颜色区分。
5. **展开新信息**：每个控件展开后呈现默认层没有的内容；无行为按钮、空区块、仅装饰切换一律不得出现。
6. **原生控件优先**：展开用原生 `<details>/<summary>`，互斥展开用同名 `name` 分组；确需 `hidden="until-found"` 时，监听 `beforematch` 同步状态，并为不支持的环境提供展开全部内容及同步 ARIA 的回退；不给原生 `<button>` 叠加 Enter／Space 键盘处理。
7. **键盘**：Tab 可达全部控件；自定义复合部件支持方向键与 Home／End；保留可见 `:focus-visible`，焦点顺序符合阅读顺序。容器设 `overflow: clip/hidden` 时不得裁掉焦点框，并须用真实键盘遍历确认，不仅凭样式推断。
8. **ARIA 与语义**：ARIA 状态与行为一致；每个 `aria-controls` 都有目标；一个 `h1`，标题逐级不跳级；标题不放在 `<summary>` 内，需作触发时用“标题包按钮”；`<html lang>` 与内容语言一致。
9. **移动端**：响应式排版用 `clamp()` 组合视口与字号单位，不单独使用裸 `vw`；390×844 视口下页面无横向滚动、文字可读；表格可在自身容器内滚动；可点目标不小于 24×24 CSS 像素，触屏环境进一步加大。
10. **如实报告**：默认层、逐节点展开、对照切换、键盘操作、移动视口与链接的实际浏览器检查未执行时，交付物必须声明未执行；页面内的验证声明同样只写实际执行的检查。
