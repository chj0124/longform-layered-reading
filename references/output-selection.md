# 输出选择契约

仅在步骤 4（设计优化结构、输出与交互）加载。目标是逻辑驱动的原文优化版：先判定内容与论证关系，再设计显式结构、引导符号、交互和可视化；形式不得创造逻辑。

## 阅读模式与删留标准

1. **原文优化版（默认）**：不是摘要，也不是全文搬运。只保留服务于逻辑、论证或理解的内容；删除废话、重复框定、离题内容和修辞性冗余。例子、过程、次要证据、限制与例外若承担说明、支撑、反驳或边界作用，必须保留其必要细节。可以重写措辞、重排顺序和合并重复内容，但不得改变论证含义。
2. **明确摘要版**：仅当用户要求摘要、要点、速读或压缩时使用。仍须保留核心论证链及使其成立的关键细节，不得宣称覆盖全文所有信息。
3. **用户给定篇幅上限**：先保留核心论证、关键例子和支撑理解的证据，再压缩重复框定与冗余表达；不得优先删除承担逻辑作用的例子过程、方法限制或次要证据。无法同时满足篇幅与必要内容时，说明取舍，不得静默省略。

## 输出形式（默认交互 HTML）

1. **用户明确指定格式** → 遵从用户；但内容关系、删留标准与论证保真仍须满足，指定格式不构成歪曲关系或保留废话的许可。
2. **单文件交互 HTML（默认）**：除下一条的简单结构外均使用。通过显式层级、论证导航、引导符号、展开细节和关系图呈现优化版；复杂逻辑必须可视化。正文与核心论证链须可直接阅读，不得全部藏入折叠控件。
3. **树状大纲（仅限简单结构）**：仅当原文基本为单主线、层级约 2—3 层以内，且不存在需要图形表达的复杂并列、前提链、共同作用、反馈、对照或局部—整体关系时使用。只要复杂关系需要可视化，就不得退成大纲。
4. **对照表**：作为 HTML 或大纲中的组件，用于两个以上主体、方案或情境共享稳定比较维度（同一列内各单元含义一致）的内容。不得仅因移动端显示顾虑降级为列表；移动端由表格容器滚动等呈现方式处理。作者判断、评价或预测置于表外就近位置并标注归属，不作为比较维度混入。列维度不稳定时改用结构化文字。
5. **多种关系并存** → 在同一 HTML 中混合使用论证图、顺序链、时间线、对照表和正文，不强制单一组件。
6. **关系不明确** → 先用结构化文字呈现，不虚构箭头或关系；这不构成默认退回树状大纲的理由，除非满足简单结构条件。

HTML 的交互控件与关系图规范见 `interaction-patterns.md`。

## 主线句与引导符号

- **默认必须有**：优化版默认层包含一条明确的短“一句话主线”，仅读该句即可知道文本讨论什么、作者如何判断。主线句是导航，不是全文替代品。
- **按体裁成形**：论述文＝核心问题＋作者判断；叙述文＝事件主轴＋结局／落点；无共识访谈＝各方共同问题＋仍存在的分歧。只取与体裁对应的一种结构，不混编。
- **一句一关系**：一句话只承载一个主关系；多个并列或嵌套关系拆句或改用关系图，不得把全部章节串进一句。
- **先概览后细节**：默认层先呈现关系概览（各部分回答什么、如何连接），再进入优化正文；不得从细节清单开始。
- **统一引导符号**：用一致的标题、编号、缩进、箭头和文字标签标明“前提、理由、证据、例子、推论、反驳、限制、结论”等角色，以及“因为／所以／但是／除非”等关系。首次出现提供简短图例；不得只靠颜色传达逻辑，同一符号不得兼指不同关系。

## 每种格式的固定要求

- **默认层（概览／导航）**：可独立把握核心问题或叙述主线，但不得被当作优化版的全部内容。
- **优化正文层**：保留所有服务逻辑或理解的必要内容，删除不服务逻辑的废话；论证型文本须能沿“主张—理由—证据/例子—推理—结论”回读，前提、反驳、限制与例外各有去处。论证链须通过就近标注、小标题或关系图显式呈现，不得只留在内部内容地图。
- **复杂逻辑可视化**：多支柱、前提链、共同作用、对照、反馈、时间和局部—整体等复杂关系，必须映射为相应图形或交互视图；不得只把复杂逻辑留在长段线性文字中。每条关系须有原文依据，推断关系单独标识。
- **例子与证据**：保留使其发挥逻辑作用的语境、过程、结果及作用（说明、证据、反例、类比等）；不得只留结论，也不得把举例自动写成证明。次要证据若服务论证或理解就保留，若与已有内容重复且无新增作用则删除或合并。
- **支持层**：呈现默认层没有的细节、引语、限定条件和来源，不得重复默认层。
- **语气与文风**：无须保留原语气或修辞风格，可改为清晰中性表达；但“可能／必然”、评价强弱、不确定性、情感所承载的事实信息与归属不得改变。
- **来源呈现**：标题、作者/说话者、出处随层标注；引语挂在其人物名下。
- **完整性声明**：输出开头或结尾保留所读范围声明（全文 / 片段）与阅读模式（原文优化 / 明确摘要），片段输入按入口的可读范围规则处理。

## 背景补充落位

仅当已按 `background-supplements.md` 判定需补时处理：大纲就近写在相关条目旁并标“背景补充（非原文）”；对照表不得为背景新增列或破坏列维度稳定，写入相关单元格附注或表下就近脚注；HTML 用相关节点旁原生 `<details>`，默认闭合。背景不进入默认层主线句，不阻塞交付；无缺口时输出零背景内容。
