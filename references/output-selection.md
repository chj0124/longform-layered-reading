# 输出选择契约

仅在步骤 4（设计优化结构、输出与交互）加载。目标是**信息完整保留的原文分层优化版**：先登记信息、判定骨架与关系，再设计短句层级、引导符号、交互和可视化；形式不得创造逻辑。

## 阅读模式与信息保留

1. **原文优化版（默认）**：不是摘要、概括或全文搬运。原文中所有有信息量的内容都须保留并可回溯，包括机制、例子、过程、数据、引语、条件、例外、限制、次要证据和旁支信息。可重写措辞、重排顺序、拆分长句和合并完全重复的信息，但不得改变或减少信息。
2. **明确摘要版**：仅当用户要求摘要、要点、速读或压缩时使用。须明确标为摘要，保留核心论证链及使其成立的关键细节，不得宣称覆盖全文所有信息。
3. **用户给定篇幅上限**：原文优化版不能靠遗漏原文信息满足上限。先移除非原文的可选背景、合并完全重复信息并压缩表达；仍冲突时，按用户对完整性与篇幅的明确排序执行，未排序则说明冲突并请求选择，不得静默省略。

## 输出形式（默认交互 HTML）

1. **用户明确指定格式** → 遵从用户；但信息覆盖、内容关系、分层与论证保真仍须满足。
2. **单文件交互 HTML（默认）**：除用户指定格式或下一条的简单结构外均使用。页面必须包含短句骨架、显式逻辑连接、下级完整细节和至少一种有信息增益的可视化结构；单一主线且只有少量节点时，不为凑图装饰。
3. **分层树状大纲（受限）**：仅当用户指定，或原文基本为单主线、层级约 2—3 层以内且不存在需要图形表达的复杂关系时使用。即使使用大纲，也须遵守信息完整和短句短段要求。
4. **对照表**：作为组件，用于两个以上主体、方案或情境共享稳定比较维度的内容。不得仅因移动端显示顾虑降级为列表；移动端由表格容器滚动处理。作者判断、评价或预测置于表外就近标注，不作为比较维度混入。列维度不稳定时改用结构化文字。
5. **多种关系并存** → 在同一 HTML 中混合使用论证图、顺序链、时间线、对照表和分层正文，不强制单一组件。
6. **关系不明确** → 用结构化短句呈现，不虚构箭头；仍可保留一级骨架和下级细节。

HTML 的交互控件与关系图规范见 `interaction-patterns.md`。

## 固定分层：骨架 → 逻辑 → 细节

### 一级：原文骨架

- 用短标题和短句节点呈现原文脉络；每个节点只回答一个核心问题，只承载一个主关系。
- 一级不得出现长段、长句、完整例子、数据堆叠或多个嵌套论证；这些信息放入对应下级。
- 默认层包含一条短“一句话主线”：论述文＝核心问题＋作者判断；叙述文＝事件主轴＋结局／落点；无共识访谈＝共同问题＋仍存在的分歧。主线只作导航，不替代正文。
- 先呈现关系概览，再进入优化正文；不得从细节清单开始。

### 骨架之间：逻辑连接

- 用一致的标题、编号、缩进、箭头和文字标签标明“前提、理由、证据、例子、推论、反驳、限制、结论”等角色，以及“因为／所以／但是／除非”等关系。
- 首次出现提供简短图例。可使用 `∥` 表示并列、`→` 表示顺序、`⇒` 表示推理、`↻` 表示反馈；同一符号不得兼指不同关系，符号旁必须有文字标签，不得只靠颜色传义。
- 一句只承载一个主关系；多个并列或嵌套关系拆句、拆节点或改用关系图。

### 二级及以下：原文信息

- 把信息清单中的细节放入所属骨架节点下一级，包括例子的语境、过程、结果与作用，以及数据口径、引语、条件、例外、限制和来源。
- 旁支信息挂在原所属部分，标为“补充／旁支”，不得因不进入主线而删除。
- 支持层提供一级没有的信息，不把一级内容原样重复一遍。
- 核心正文和论证链保持连续可读；折叠用于辅助细节、背景和按需下钻，不得迫使读者逐点点击才能理解原文。

## 短句短段预算（全部层级适用）

以下是可读性预算，不是删减信息的理由：

1. 一级节点标题尽量不超过 24 个汉字；节点说明至多两句，每句只表达一个主关系。
2. 普通句子以不超过 50 个汉字为默认上限；超过时优先拆句、拆列表或改用关系标签，不得靠删条件、限制或归属来缩短。
3. 普通段落控制在 1—3 个短句且不超过 150 个汉字；超过时拆段或改为列表，不形成文字墙。
4. 必须原样保留的长引语、法条、代码或特殊格式可例外，但应使用独立引用块、分段或展开控件，并保留完整语境；不得改写后仍冒充原话。
5. 拆分后不得制造重复。每个新段落必须有新的信息或明确的逻辑职责。

## 每种格式的固定要求

- **默认层（概览／导航）**：可独立把握主线，但不得被当作优化版全部内容。
- **优化正文层**：所有原文信息均有落位；论证型文本可沿“主张—理由—证据／例子—推理—结论”回读，前提、反驳、限制与例外各有去处。
- **可视化信息图表**：多节点 HTML 默认至少提供一幅结构总览；复杂关系分别进入相应图形或交互视图。图形须减少、重组或显化关系，不得与同等长度正文重复。
- **例子与证据**：保留使其发挥作用的完整信息，不得只留结论，也不得把举例自动写成证明。
- **语气与文风**：可改为清晰中性表达，但“可能／必然”、评价强弱、不确定性、情感所承载的信息与归属不得改变。
- **来源呈现**：标题、作者／说话者、出处随对应节点标注；引语挂在人物名下。
- **完整性声明**：输出开头或结尾标注所读范围（全文／片段）与阅读模式（原文优化／明确摘要）；原文优化版附信息覆盖核对结果，不用“无遗漏”替代实际清单。

## 背景补充落位

仅当已按 `background-supplements.md` 判定需补时处理：大纲就近写在相关条目旁并标“背景补充（非原文）”；对照表不为背景新增列，写入相关单元格附注或表下就近脚注；HTML 用相关节点旁原生 `<details>`，默认闭合。背景不进入一级主线句，不阻塞交付；无缺口时输出零背景内容。
