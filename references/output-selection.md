# 输出选择契约

仅在步骤 4（选择输出与层级）加载。先判断内容关系，再选形式；形式不得反向创造逻辑。

## 选择规则（按可观察条件）

1. **用户明确指定格式** → 遵从用户；但内容关系仍须保真，指定格式不构成歪曲关系的许可。
2. **纯文字** → 当：线性顺序足以表达内容关系；层级较浅（约 2—3 层以内）；不存在稳定的对照维度；交互不会带来理解增益。这是默认形式。
3. **对照表** → 当：两个以上主体、方案或情境共享稳定的比较维度（同一列内各单元含义一致），且支持内容不需要深层嵌套。列维度不稳定时退回纯文字。
4. **交互 HTML** → 当：存在有价值的多层信息或非线性关系（展开能看到默认层没有的细节、引语或限定条件），且展开、切换或对照能显著降低阅读负担。交互后必须出现新信息；不得重复默认层文字或仅承担装饰。
5. **多种关系并存** → 允许混合组件（如时间线配对照表），不强制单一形式。
6. **关系不明确或各形式差异不大** → 选择负担较低的形式；不得以"更高级"为由升级成 HTML。

用户指定 HTML 时，仍须满足归属、范围与保真清单；交互控件规范见 `interaction-patterns.md`（步骤 4 选定 HTML 时加载）。

## 主线句规则

- **单一职责**：一句话主线只承载核心问题或核心判断之一；不得把引子、全部部分、结论、限制连续塞进同一嵌套长句。
- **一句一关系**：一句话只承载一个主关系；出现多个并列或嵌套关系（如“A 造成 B，同时 C 抽走 D”）时，拆成多句，或改用关系图表达，不得在句内堆叠。
- **先概览后细节**：多部分内容的默认层先呈现关系概览（各部分各自回答什么、指向什么），再呈现各部分细节；默认层不得从细节清单开始。

## 每种格式的固定要求

- **默认层**：可独立阅读，覆盖核心问题或叙述主线。
- **支持层**：呈现默认层没有的信息（细节、引语、限定条件、来源），不得重复默认层。
- **来源呈现**：标题、作者/说话者、出处随层标注；引语挂在其人物名下。
- **完整性声明**：输出开头或结尾保留所读范围声明（全文 / 片段），片段输入按入口的可读范围规则处理。

## 背景补充落位

仅当已按 `background-supplements.md` 判定需补时处理：纯文字就近写在相关条目旁并标“背景补充（非原文）”；对照表不得为背景新增列或破坏列维度稳定，写入相关单元格附注或表下就近脚注；HTML 用相关节点旁原生 `<details>`，默认闭合。背景不进入默认层主线句，不阻塞交付；无缺口时输出零背景内容。
