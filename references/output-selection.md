# 输出选择契约

两档均在实现输出前加载。目标是**短主线、具体关系、完整细节**：先确定主阅读路径和具体桥接，再选择能够清楚表达结构的最简单形式。

## 阅读模式与信息保留

1. **原文优化版（默认）**：所有有信息量的内容均保留并可回溯。主线只保留核心理解所需内容；例子、过程、数据、引语、条件、例外、限制、次要证据和旁支进入就近细节层，不因「次要」而删除。
2. **明确摘要版**：仅当用户要求摘要、要点、速读或压缩时使用；须明确标为摘要，不宣称覆盖全文所有信息。
3. **主线时长**：长文默认 3—5 分钟，不设原文字数比例；短文不填充。实测与估算分开报告，不能把估算写成实测。
4. **用户另有总篇幅上限**：先移除非原文背景、合并完全重复信息并压缩表达；仍与完整保留冲突时，按用户明确排序执行，不静默省略。

## 输出形式：够用即可，复杂才升级

按以下顺序判断，而不是默认 HTML：

1. **用户明确指定格式** → 遵从用户；仍须满足信息覆盖、具体关系、主线预算和保真要求。
2. **Markdown 分层树状大纲** → 原文以单主线或清晰并列为主，层级约 2—3 层，缩进与编号能够表达阅读顺序，且没有必须空间呈现的跨分支、汇聚或反馈关系时优先使用。长文并不必然需要 HTML。
3. **单文件交互 HTML** → 多线并行、跨板块连接、分支汇聚、反馈、频繁对照，或总览与局部推导需要联动，树状大纲会让读者自行补关系时使用。交互必须有理解收益。
4. **对照表（组件）** → 两个以上主体或方案共享稳定比较维度时嵌入大纲或 HTML；维度不稳定时改用结构化文字。
5. **关系不明确** → 保留结构化短句和原文顺序，不虚构箭头，也不为形式统一强行升级 HTML。
6. **多种关系并存** → HTML 中可混合论证图、顺序链、时间线、对照表和分层正文；不要求每篇文章同时出现所有视图。

HTML 的关系图、交互和紧凑排版规范见 `interaction-patterns.md`。日常档优先从 `assets/compact-reading-template.html` 复制并替换文章内容，不为每篇重新设计公共样式；关系需要新增结构时仍以原文为依据，不向固定模板硬塞内容。

## 固定分层：主阅读路径 → 具体连接 → 按需细节

### 主阅读路径

- 用编号、短标题和短句节点呈现阅读顺序；每个节点只回答一个具体问题。
- 开头用极短导航说明核心问题与作者主张／事件主轴／共同问题；不得用导航替代主线。
- 主线包含结论成立不可缺少的关键反方、条件和边界；完整例子、数据堆叠和嵌套过程进入细节层。
- 长文主线以 3—5 分钟读完为目标。Markdown **校验工作稿**用约定注释标记范围，HTML 用 `data-main-reading-path` 标记容器；Markdown 交付稿不得保留主线注释。旁证、回帖、推广和其他支持层放在主线标记之外；结构总览只写短骨架，不重复各节完整句。

### 板块之间：具体连接

- 每个关键连接写出「起点具体内容＋因为／通过／但是／若等推理或条件＋终点具体内容」。
- 「前提、理由、证据、反驳、限制」等角色和「独立支撑、共同作用」等类型可作辅助标签，不得代替桥接句。
- 阅读顺序本身需要解释：读者应能看出为什么此刻进入下一板块。
- 首次使用符号时提供简短图例；同一符号不得兼指不同关系，不只靠颜色传义。

### 按需细节层

- 每个细节只设一个主要主线父节点；一个主线可挂多个细节，其他关联只作交叉引用。细节标题应体现它补充父节点的哪一部分，不另起一套全文目录。
- Markdown 工作稿将细节放在主线结束标记后，按所属主线父节点分组。默认用「细节见 D1」「返回主线 M1」等编号文字双向定位；只有明确知道目标阅读器支持相应锚点时，才使用可点击页内链接，不为链接默认插入 `<a id="…">` 等原始 HTML。HTML 通过原生展开或下钻实现。
- 工作稿若使用页内链接，链接可见文字必须包含目标编号，例如 `[细节见 D1：诊断背景](#d1)`、`[返回主线 M1](#m1)`，使交付脚本转成文字导航后仍保留目标。
- 细节包括例子的语境、过程、结果与作用，以及数据口径、引语、条件、例外、限制和来源。
- 核心正文与论证链无需逐点点击即可连续阅读；不得把核心内容藏入折叠层来制造「短页面」。

#### 集中细节区的使用条件

Markdown 使用独立「按需细节」区保持主线连续时，必须同时满足：

1. 每个相关主线节点提供带目标编号的细节定位，每个细节节点提供带目标编号的返回定位；默认是文字导航，确认阅读器支持时才升级为链接。
2. 标明细节的主要父节点；一对多或多对一关系显式写出，不用编号制造一一对应的假象。
3. 从主线到细节、从细节返回主线均只需一次明确查找或跳转，读者无需扫描无关细节标题。
4. 集中置后仍须通过下述增量测试，不能形成需要重新通读的压缩版全文。

「就近」因此指导航上的直接可达，不只指物理位置相邻，也不强制要求可点击链接。

#### 细节增量测试

每个细节节点必须能回答：「除去必要的定位句后，它相对主线新增了什么？」新增内容至少属于以下一类：

- 完整语境或原始问答；
- 数据、例子或过程；
- 条件、例外或限制；
- 引语及其说话语境；
- 对主线结论的次要支撑或反证。

若只是用不同措辞重述主线，应合并或删除重复，不保留为独立细节。完整引语和必要回认句可以例外；不得为通过增量测试而补入原文没有的信息。

### 主详结构反例

```text
反例：
主线：M1—M6，六个同级问题。
细节：D1—D8，八个同级问题。
两层没有父节点或链接，且 D1 同时支撑 M1、M2。

判定：
即使主线时长合格、原文信息完整，也不通过。
原因：读者仍需自行归组、建立映射并识别重复。
```

## 短句短段预算

以下是可读性预算，不是删减信息的理由：

1. 主线节点标题尽量不超过 24 个汉字；节点说明至多两句，每句只表达一个主关系。
2. 普通句子以不超过 50 个汉字为默认上限；超过时优先拆句、拆列表或改用具体桥接，不靠删条件、限制或归属缩短。
3. 普通段落控制在 1—3 个短句且不超过 150 个汉字；超过时拆段或列表化。
4. 必须原样保留的长引语、法条、代码或特殊格式可例外，使用独立引用块或细节层并保留完整语境。
5. 拆分后不得制造重复；每个新段落必须有新信息或明确逻辑职责。

## 各格式共同要求

- **主阅读路径**：可独立理解核心论证，不替代完整细节层。
- **完整信息层**：所有原文信息有落位，论证型文本可沿「主张—理由—证据／例子—推理—结论」回读。
- **例子与证据**：保留使其发挥作用的完整信息，不把举例自动写成证明。
- **语气与归属**：可改为清晰中性表达，但立场强弱、不确定性、情感和归属不变。
- **来源呈现**：标题、作者／说话者、出处随对应节点标注。
- **完整性声明**：标注所读范围、阅读模式、执行档位、实际覆盖核对方式、同级归组／主详挂接／细节增量／按需定位的实际执行情况，以及主线时长为实测、估算或未验证。日常档未建正式清单时写「已逐段回查，未做逐项编号审计」；完整档记录逐项落位与未落位数。未执行的结构检查不得写成通过。

## 背景补充落位

仅按 `background-supplements.md` 的双门槛处理：大纲就近标「背景补充（非原文）」；HTML 用节点旁原生 `<details>`。背景不进入主线，不阻塞交付；无缺口时输出零背景内容。
