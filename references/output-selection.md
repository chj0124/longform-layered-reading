# 输出形式选择

格式服务于关系，不服务于视觉效果。两档使用相同的内容保真标准。

## 快速判断

| 结构特征 | 优先形式 | 原因 |
|---|---|---|
| 一条主线依次推进 | Markdown | 阅读路径短，无需额外交互 |
| 三层以内并列大纲 | Markdown 树状列表 | 层级本身已足够清楚 |
| 多主体、多支线 | 单文件 HTML | 可用导航与关系图呈现分合 |
| 跨章节回指、汇聚、反馈、循环 | 单文件 HTML | 纯线性排列容易掩盖关系 |
| 用户明确指定 | 指定形式 | 保持相同的信息与桥接标准 |

不确定时先用 Markdown。不能为了展示能力把简单文章做成网页。

## Markdown 规范

- 用标题表达阶段问题，用列表表达并列或层级。
- 主阅读路径直接写出，不用引用块藏起关键判断。
- 细节放在明确的「按需细节」小节；若渲染环境支持，可用原生 `<details>`。
- 具体桥接直接写成完整句或 `起点 → 推理／条件 → 终点`。
- 若使用标记，主线容器加 `main-reading-path:start/end` 注释，便于验证脚本定位。

```markdown
<!-- main-reading-path:start -->
## 核心问题
……
## 推导
……
<!-- main-reading-path:end -->

## 按需细节
……
```

## HTML 规范

- 单文件，保存后可离线打开。
- 主线容器带 `data-main-reading-path`，默认直接可见。
- 细节使用原生 `<details>/<summary>`，不依赖 JavaScript。
- 日常档优先从 `assets/compact-reading-template.html` 复制并替换文章内容，不为每篇重新设计公共样式。
- 页内导航使用真实 `id`；图与正文共用具体桥接。
- 页脚或说明区注明执行档位、覆盖范围与验证方式。

日常档复用模板不代表免于当前产物检查；至少完成打开、主线、展开、链接和占位符冒烟。完整档或模板／交互变更时执行相应完整检查。

## 图形使用门槛

只有当图形能比文字更少地表达分合、反馈、多主体或条件分支时才使用。否则保留树状文本。

图形不得引入正文没有的关系；图形标签必须具体，不使用只有「阶段一／阶段二」的空节点。

## 时长说明

主线 3—5 分钟是设计目标。可用文本长度作估算，但必须标明估算口径；真实读者测试与文本估算不能混称。

## 完整性声明

无论格式如何，交付说明都应包括：

- 阅读模式（Markdown／HTML）。
- 执行档位（日常／完整）。
- 实际覆盖范围。
- 核对方式（逐段回查／逐项编号审计）。
- 未验证事项（如有）。
