# 主阅读路径与具体桥接

两档都使用本文件。`M／D` 可挂在日常档的轻量内容草图上，也可挂在完整档的正式内容地图上；分层标准不变。

## 1. 先找核心问题，再选主线

用一句话写出：读者读完主线后，应该能回答什么？

主线通常包含：

1. 核心问题。
2. 作者的关键回答。
3. 不读就理解不了该回答的推导。
4. 会改变结论边界的关键条件。
5. 收束或行动含义（原文有的话）。

不是所有背景都放开头，也不是所有例子都放细节。若某个例子是推导成立的唯一桥梁，它必须进入主线。

## 2. M／D 分层

- `M`：删除后核心问题、关键判断或推导链断裂。
- `D`：删除后主线仍成立，但证据、限定、背景、例子或可核验性减少。
- 同义重复：合并，不占用两个节点。
- 独立事实与边界：无论 `M／D` 都必须保留。

`D` 可以折叠，不能省略。日常档省略的是正式登记，不是这些信息。

## 3. 主线长度

以 3—5 分钟读完为目标，不设固定压缩比例。先保证核心论证能读懂，再压缩重复表达。

文本估算只用于设计反馈。不要写成「真实读者平均 3 分钟读完」，除非确实做了读者测试。

## 4. 具体桥接

每次重要推进尽量能写成：

```text
起点具体内容 → 推理过程／成立条件 → 终点具体内容
```

检查三个位置：

- **起点**：具体是谁、什么现象、什么判断？
- **中间**：通过什么机制、证据、对比或条件？
- **终点**：因此得到哪个具体结论？结论范围是什么？

只写「A 支撑 B」「A 导致 B」不合格。若作者没有解释中间机制，正文写「作者据此认为」，不要补造机制。

## 5. 跨板块连接

至少检查：

- 前一板块的结论是否是后一板块的前提？
- 后文是在举例、限定、反驳还是转换话题？
- 后文的代词与「因此」具体回指哪一项？
- 两条支线在哪里汇聚，汇聚后改变了什么判断？
- 反馈关系的方向是否被写反？

日常档可在轻量草图旁内部核对这些桥接要素；完整档应把关键桥接登记在正式表格或验证记录中。两档正文都必须把必要桥接写给读者。

## 6. 顺序重排边界

可以把原文后面才出现的回答提前，以避免读者长时间没有方向；但应保留必要回指，不能让读者误以为作者按新顺序论证。

不得通过重排：

- 把先后事件改成因果。
- 把反例移到结论之后以制造无争议假象。
- 把不同主体的行为合并。
- 把条件结论写成无条件结论。

## 7. 收束测试

遮住细节层，只读主线：

- 能否说出作者的问题与回答？
- 能否复述至少一条具体推导，而非只记住结论？
- 是否知道结论在哪些条件下成立？
- 是否遇到只有抽象词、没有具体内容的箭头？

再展开细节：

- 是否能找到主线判断对应的例子、数据、反例或限定？
- 是否出现原文有、交付物却无处可找的信息？

任一关键答案为否，先修结构，不做视觉润色。
