# 保真与呈现校验

先按执行档位核对内容，再按实际输出核对呈现。日常档没有正式 `Sxxx` 清单不等于失败；没有实际逐段回查却声明已回查，才是失败。

## 一、两档共同的内容硬门槛

### 原文范围

- [ ] 已说明实际取得的是全文还是部分文本。
- [ ] 没有用链接标题、搜索摘要或开头段落代替完整原文。
- [ ] 原文中的逻辑缺口没有被改写成已解决的问题。

### 主线与细节

- [ ] 主线能独立回答核心问题，而不是只有几个结论标题。
- [ ] 主线以 3—5 分钟读完为目标，但没有为压缩篇幅删断推导。
- [ ] 每个 `D` 细节都能在交付物中找到，不是「详见原文」。
- [ ] 删除测试已执行：断推导者进主线，仅减少支撑者进细节。
- [ ] 同义重复已合并，独立事实、例子、数字、归属和边界没有随之删除。

### 具体桥接

- [ ] 关键推进包含起点具体内容、推理／条件、终点具体内容。
- [ ] 跨章节箭头没有只写「支撑」「导致」「因此」。
- [ ] 时间先后没有被误写成因果。
- [ ] 作者推断与重组者推断已区分。
- [ ] 图形、导航标签和正文使用的是同一套关系，不互相矛盾。

### 事实与边界

- [ ] 数字、日期、引语、人物、机构与动作归属一致。
- [ ] 条件、例外、反例、替代解释和不确定性保留。
- [ ] 作者观点没有被写成无归属的客观事实。
- [ ] 没有为了结构整齐而补入原文没有的机制或结论。

## 二、日常档最低记录

- [ ] 已建立足以辨认板块、核心判断、关键支撑与关系的轻量内容草图。
- [ ] 已按原文顺序逐段回查，而非只复读自己的输出。
- [ ] 回查覆盖主线、细节、桥接、数字、归属和结论边界。
- [ ] 交付说明写明实际范围与核对方式。
- [ ] 未强制附带 `Sxxx` 表、完整内容地图或逐项覆盖表。

完成实际回查后可声明：

```text
已逐段回查，未做逐项编号审计。
```

如果命中回退信号，记录回退原因，并按完整档补做相应检查。

## 三、完整档追加审计

- [ ] `Sxxx` 编号连续，且每个信息单元有唯一主要落位。
- [ ] 未落位项为 0；合并项有去向；未读范围已声明。
- [ ] 已统计原文、保留／改写、合并、未读、未落位数量。
- [ ] 主线与细节节点、关键连接和具体桥接数量有记录。
- [ ] 正文没有让同一信息在多个节点无意义地完整重复。
- [ ] 覆盖表与实际正文一致，不是交付前另写的一份形式记录。

## 四、HTML 与修订检查

### 日常档：当前产物冒烟

即使复用已验证模板，也要对当前文章实例实际检查：

- [ ] 页面能打开，标题、主线和当前文章内容正确。
- [ ] 主线直接可见；原生展开控件能展开、关闭，展开后非空。
- [ ] 页内链接有目标；没有模板占位符残留。
- [ ] 没有因替换内容造成明显断裂、空白或外部资源依赖。

### 完整档或模板／交互变更：完整呈现验证

按变更范围读取 `validation/cases/html-interaction.md`，实际执行并保存报告：

- [ ] 桌面与移动视口可读，无页面级横向溢出。
- [ ] 主线无需点击即可阅读，展开顺序与内容结构一致。
- [ ] 键盘焦点可见，Tab 顺序合理，原生控件可用 Enter／Space 操作。
- [ ] 控制台无当前产物引入的错误，无意外外部请求。
- [ ] 若修改了样式或交互，复测受影响项目，而非沿用历史结果。

真实触屏、屏幕阅读器、读者实测或独立盲评未执行时，明确写未执行。

## 五、两档对照与速度声明

同一篇文章比较两档时：

- [ ] 对照正文实质内容，而非只比较文件长度。
- [ ] 日常档不得比完整档少主线、细节、例子、数字或边界。
- [ ] 两档可以有不同的内部记录与审计附件。
- [ ] 没有独立计时就不写具体提速比例。
- [ ] 阅读时长脚本结果标为文本估算，不称为真实读者测试。

## 六、交付声明

声明必须与实际行为一致，至少包含：输出形式、执行档位、实际覆盖范围、核对方式。若有时长或验证，注明类型和范围。
