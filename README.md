# Longform Layered Reading

面向各种长文的逻辑驱动优化技能。默认产物不是摘要或全文搬运，而是**原文的交互式优化版本**：只保留服务于逻辑、论证或理解的内容，删除废话与修辞性冗余，通过显式结构、统一引导符号和可视化暴露原文隐藏的论证关系。

默认交付单文件交互 HTML；仅当原文结构实在简单、静态树状大纲已足够时使用大纲。复杂逻辑必须在 HTML 中可视化。语气与文风可中性化，但立场强度、不确定性和归属必须保留。

适用于论说文章、论文、行业报告、访谈、历史与调查叙事，以及混合型长文。

请把 GitHub 仓库 https://github.com/chj0124/longform-layered-reading 克隆到当前 Agent 的用户级技能目录（优先使用 ~/.agents/skills/longform-layered-reading；若你的 Agent 使用其他技能目录，请按其文档安装），保留 SKILL.md 和 references 的完整结构，重新加载技能后用一次长文交互式优化任务验证安装。

## 核心能力

- 记录原文来源与实际可读范围，不把片段伪装成全文。
- 默认提供单文件交互 HTML 的原文优化版；仅简单结构使用树状大纲。
- 所有内容服务于逻辑、论证或理解；删除废话、重复框定和修辞性冗余。
- 保留承担逻辑作用的机制、例子、过程、次要证据、限制与例外。
- 显化「主张—理由—证据/例子—推理—结论」，保留前提、反驳、限制与例外。
- 用一致的标题、编号、箭头与逻辑标签暴露隐藏结构；推断关系单独标识。
- 将多支柱、前提链、共同作用、对照、反馈、时间和局部—整体等复杂逻辑可视化。
- 区分例子的说明、证据、反例或类比作用，不把举例自动当证明。
- 区分原文陈述、作者判断、预测、有限旁证和不同人物的声音。
- 语气与文风可中性化，但立场强度、不确定性、评价归属和论证含义不变。
- 只在知识缺口阻碍理解时就近补充简短背景，并明确标为非原文。
- 交付前检查逻辑覆盖、删留依据、论证、可视化、归因、分层和验证声明。

## 安装

将本仓库克隆到运行环境的用户技能目录：

```bash
git clone https://github.com/chj0124/longform-layered-reading.git "$HOME/.agents/skills/longform-layered-reading"
```

在 Windows 的 Kimi Code 中，对应目录为：

```text
C:\Users\<用户名>\.agents\skills\longform-layered-reading\
```

安装后重新加载会话或技能目录，使技能出现在可用列表中。

## 使用

直接提供完整正文、文件或公开链接，例如：

```text
请阅读这篇长文，并按 longform-layered-reading 生成原文的交互式优化版本：删去废话，保留逻辑相关细节，用结构和图形展示论证：
https://example.com/article
```

也可以指定输出形式或明确摘要需求：

```text
把这篇访谈优化成交互 HTML，保留各方语境与例子，并可视化共识和分歧。
这篇短文的结构很简单，用树状大纲呈现即可。
把这篇报告压缩成 1000 字摘要，保留关键证据和限制。
```

未指定格式时，技能按以下原则选择：

| 输出形式 | 适用条件 |
|---|---|
| 单文件交互 HTML | 默认；用显式结构、引导符号、交互与图形呈现优化正文，复杂逻辑必须可视化 |
| 树状大纲 | 仅用于单主线、层级浅、没有复杂关系需要可视化的原文 |
| 对照表（组件） | 多个主体或方案共享稳定、同义的比较维度时，嵌入 HTML 或大纲 |

## 目录结构

```text
longform-layered-reading/
├── SKILL.md
└── references/
    ├── text-structures.md
    ├── output-selection.md
    ├── interaction-patterns.md
    ├── background-supplements.md
    └── fidelity-checklist.md
```

- `SKILL.md`：触发条件、核心原则和不可跳过的工作流。
- `text-structures.md`：不同文本类型的识别信号与内容地图要求。
- `output-selection.md`：原文优化／明确摘要模式、默认 HTML／简单大纲、逻辑删留、引导符号与可视化契约。
- `interaction-patterns.md`：文本关系到交互结构的映射及 HTML 实现要求。
- `background-supplements.md`：仅在知识缺口阻碍理解时加载，规定背景的归属、预算和就近落位。
- `fidelity-checklist.md`：交付前的覆盖、关系、归因与数值校验。

参考文件按任务需要读取，不必每次全部加载。

## 维护与验证

修改技能时，建议采用以下流程：

1. 用无技能的全新上下文运行目标场景，记录实际失败。
2. 只针对已观察到的失败编写最小规则。
3. 用加载技能后的全新上下文重跑相同场景。
4. 保留基线、输出和独立复核证据，再安装或发布。
5. 修改 HTML 交互规则时，实际检查展开、键盘、焦点、移动端和链接。

当前验证覆盖论说、访谈、研究、叙事、混合文本、不完整输入和 HTML 场景。浏览器 console 采集与合成触屏分发未验证，不应被视为已通过。
