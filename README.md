# longform-layered-reading

把长文重构为「短主线＋具体推导＋完整细节」的分层阅读稿。主阅读路径以 3—5 分钟读完为目标；二级支撑、限定条件、例子、数据与反例按需展开，不因压缩主线而省略。

它不追求把全文压成摘要，而是把原文的推导顺序、段落关系和证据位置重新组织，让读者先沿一条短路径读懂，再决定展开哪里。Markdown 树状大纲与交互 HTML 共用同一套内容规则。

## 使用方式

把整个技能目录放入你的 Agent 技能目录，或分发打包后的 `.skill` 文件。安装后可直接说：

```text
用 longform-layered-reading 处理这篇文章，保留完整细节，主线控制在 3—5 分钟。
```

也可以指定：

```text
用 Markdown 树状大纲呈现，不要先做网页。
```

```text
这条主线涉及多个角色的相互作用，用紧凑的交互 HTML 呈现。
```

## 执行档位

默认使用日常档：直接给可读版本，按原文顺序逐段回查，不强制生成正式 `Sxxx` 信息清单、完整内容地图或用户可见的逐项覆盖表。HTML 复用紧凑模板，减少重复设计。

需要正式交付、逐项覆盖核验，或遇到结构不稳、事实与关系存疑、主线断裂、呈现模板变更时，回退完整档。两档的正文保真要求相同，区别只在底稿、覆盖记录和呈现验证强度。

| 档位 | 默认行为 | 交付记录 |
|---|---|---|
| 日常档 | 轻量内容草图＋逐段回查；复用已验证模板 | 简短说明实际核对范围；不强制逐项编号审计 |
| 完整档 | 完整信息清单、内容地图、唯一主要落位与完整审计 | 保存覆盖清单、数量、未落位项和相应验证报告 |

可直接指定：

```text
用日常档处理这篇文章，保留全部有信息量的细节。
```

```text
用完整档处理，并给出逐项覆盖核验。
```

## 它解决什么问题

- **主线太长**：核心问题、关键判断和结论分散在长文中，读者难以先获得整体方向。
- **结构不可见**：并列、条件、因果、转折、让步、反驳和证据关系混在连续段落里。
- **连接太抽象**：流程箭头只写「导致」「支撑」，看不出从什么具体内容，经过什么推理，到达什么判断。
- **长句难拆**：多层修饰、嵌套关系和长并列提高理解成本。
- **简化就丢信息**：普通摘要常把例子、数字、限定条件和反例一起删掉。
- **长文容易弃读**：即使内容有价值，读者也可能在到达核心论证前离开。

## 输出长什么样

### 主阅读路径

默认直接展示，读者无需先点击：

1. **核心问题**：作者究竟要解释或判断什么。
2. **关键回答**：作者的核心判断及其成立条件。
3. **具体推导**：每个阶段从什么具体内容，经过什么推理，得到什么结果。
4. **证据与边界**：关键例子、数据、反例和结论适用范围。
5. **收束**：作者最终让读者如何重新理解问题。

主线尽量短，但不是预先规定压缩比例。若核心论证尚未读懂，就不能为了控制篇幅继续删减。

### 按需细节层

主线之外保留：

- 支撑核心判断的二级理由；
- 关键概念的展开解释；
- 例子、数据、引语及其具体归属；
- 限定条件、例外、反例和替代解释；
- 对理解有帮助、但不适合塞进主线的背景。

不能保留「详见原文」「若干原因如下」等没有实际信息的占位文字。

### 具体桥接

跨章节或跨阶段的关系至少能还原为：

```text
起点具体内容 → 推理过程／成立条件 → 终点具体内容
```

例如，不写「就业变化 → 消费变化」，而写清楚哪类就业变化，通过收入预期或风险判断，影响哪类消费决定。

## Markdown 还是 HTML

| 文本关系 | 优先输出 |
|---|---|
| 单主线、清晰并列、浅层级 | Markdown 树状大纲 |
| 多线并行、跨章节回指、汇聚、反馈、循环 | 单文件交互 HTML |
| 用户明确指定格式 | 尊重指定，同时保持相同的信息完整性 |

HTML 采用紧凑布局，不制作封面式长滚动页。默认日常档从 `assets/compact-reading-template.html` 复制并替换文章内容，不为每篇重新设计公共样式。主线直接可见，细节用原生 `<details>/<summary>` 展开；无 JavaScript 依赖，保存后可离线阅读。只有关系图能明确降低理解成本时才绘制，图形必须与正文使用相同的具体桥接。

## 信息完整性原则

- 两档都先完整阅读，再重构，不根据标题或开头猜全文。
- 日常档使用轻量内容草图，并按原文顺序逐段回查；完整档建立信息清单和内容地图。
- 完整档的每项信息只有一个主要落位，其他位置只做必要回指。
- 事实、观点、推断和重组注释分开表达。
- 保留数字、时间、主体、动作、原因、条件和结论边界。
- 无法确认的关系不补写为确定因果。
- 原文缺失时先声明范围，不假装已覆盖全文。
- 交付声明必须与实际执行档位和核对方式一致，未逐段回查不得声称已经回查。

## 维护与验证

规则、模板或脚本修改后，按变更范围运行验证，不把历史模板结果冒充当前产物结果。同一篇文章做日常／完整两档对照时，检查正文是否出现信息差；没有独立计时就不报告具体提速比例。完整方法见 `validation/README.md`。

纯文本改动不强制重跑浏览器测试；日常档的固定模板复用也不自动要求全量 HTML 测试。HTML 模板、样式或交互变更，才需重跑受影响的桌面、移动、键盘和控制台检查。

验证材料使用仓库内合成文本，不依赖外部文章持续可访问。真实文章试读可用于发现体验问题，但不能替代边界用例。
